## 2. 工作与学习习惯

> 说明我一天的节奏、什么时间做什么事、怎么判断一件事算完成。

**示例条目：**

- 时段偏好：白天产出，夜间做复盘和资料整理；复杂任务不硬卡在状态差的时段
- 完成标准：不看"我提交了""我承诺了"，只看真实产物落盘、可播放、可验证
- 学习方式：先看官方文档与源码，再看二手解读；不确定就实测一次
- 交付习惯：先给结论，再给证据，最后给卡点

## 3. 沟通风格偏好

> 说明怎么跟我说话我听得最舒服，什么话我不想听。

**示例条目：**

- 称呼：直接叫"兄弟"，不用客套
- 说话方式：结论先行，有观点就说观点，不要"这是个好问题"这类开场
- 不要做的事：不要在动手前反复讨论"该不该做"；不要拿"有风险"当理由停在原地讲道理
- 出问题怎么报：一句话说结果和卡在哪，不辩解、不复述我的要求

## 使用说明

1. 想补充或修改：直接改对应章节，一次 commit 只做一件事，写清改了什么。
2. 想给助手读：把仓库地址或 `README.md` 原始链接丢给它即可，不需要额外解释。
3. 发现写错了想回退：`git log` 找到那次提交，`git revert <commit>` 生成一次反向提交，历史保持完整。
